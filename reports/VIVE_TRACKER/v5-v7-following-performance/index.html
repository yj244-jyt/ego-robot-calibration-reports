01 · Decision boundary

这批数据能说明什么

结论严格限定在两条软件数据流的相对表现，不把软件侧读取或发布时间误写成硬件级物理延迟。

可以直接支持

  • Vive 稳定复现 TCP 的 X 向往复趋势，三组相关系数均大于 0.9999。
  • 0.5 m/s 条件下空间残差高于 0.2 m/s，且时延补偿后差异仍存在。
  • 当前可观测 Vive 数据流相对 Robot state 约早 3–5 ms。
  • 三组均无无效 Vive 帧、无明显采集断流、无随时间累积漂移。

不能由当前数据单独证明

  • 不能证明 Vive 传感器在物理上“提前”看到运动。
  • 不能把 v6 的误差增量全部归因于 Vive 的高速动态跟随。
  • 不能分离 OpenXR 预测、Robot state 时序、外参、杆臂和结构弹性的独立贡献。
  • 不能把 v5、v6、v7 简化为严格的单变量速度扫描。

05 · Shared evidence & small differences

一致点、微小区别与共同可比项

三组一致点

  • 均完整复现 X 向往复运动，相关系数超过 0.9999。
  • 均没有无效 Vive 帧，最大帧间隔均小于 23 ms。
  • 两种时延估计均为负值，方向一致。
  • 补偿相对时延后 RMSE 均下降，改善范围为 16.7%–36.3%。
  • 有符号均值绝对值均小于 0.4 mm，没有明显固定 X 偏置。

微小区别

  • v7 相关系数最高，但过阈值事件最少、时延离散度最大。
  • v5 的静态初始化平移离散度最低于 v7，但高于 v6。
  • v6 的最大姿态变化为 2.17°，明显高于另外两组。
  • v5 行程仅 0.1 m，循环频率和加减速占比与 v6/v7 不同。
  • v6 空间误差最大，但并未出现额外丢帧或采集断流证据。

07 · Analysis method

同一数据，三种观察方式

采样与时间统一

  • 以每个真实 Vive 源帧为基准。
  • 在对应时刻对 Robot state 做线性插值。
  • 不把 Vive 插值为更高频的伪帧。
  • 通过采集前后时钟交换，把时间统一到 Robot 时钟域。

残差定义

X residual = Vive 相对 X − 对齐到 Vive 帧时刻的 Robot 相对 X

绝对值越小，表示两条轨迹的 X 位移越一致。有符号均值用于检查固定方向偏置。

同墙上时间

直接在 Vive 帧时刻比较插值后的 Robot X 与 Vive X，同时包含相对链路时延和空间测量误差。

两种时延补偿

  • 互相关：5 ms 网格搜索整段轨迹相关性最高的时移。
  • 过阈值：比较两条轨迹同方向通过相同 X 阈值的事件时刻，以中位数作为时延。

08 · Final verdict

最终判断

1
运动趋势稳定。

在 0.2–0.5 m/s 范围内，Vive Tracker 没有丢失 X 向往复运动趋势，也没有出现明显滞后或累计漂移。

2
可观测时序略早。

Vive 软件数据流相对 Robot state 约早 3–5 ms；这是系统级相对时序，不是 Vive 绝对传感延迟。

3
高速残差仍为毫米级。

v6 在 0.5 m/s、0.3 m 行程下，同墙上时间 P95 为 3.371 mm、最大值为 4.685 mm；过阈值补偿后 P95 为 2.642 mm、RMSE 为 1.395 mm。

4
误差增大确定，来源占比未分离。

动态误差、Robot state 时序、TCP 姿态变化、外参与杆臂误差都可能贡献 v6 的增量。

下一轮最有价值的改进：固定 0.3 m 行程与完全相同的 TCP 姿态轨迹，仅扫描速度；同时记录 OpenXR 原生预测时间、主机接收时间和机器人伺服侧时间，并重复多轮估计置信区间。这样才能把“速度效应”与“时序/姿态效应”进一步拆开。
